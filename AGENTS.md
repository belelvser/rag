# Правила работы над проектом

- Это небольшой учебный RAG-проект. Пользователю важно понимать код.
- Выполнять только текущий согласованный этап. Сейчас это этап 8: полностью контейнеризированный запуск через Docker Compose с API, агентом и одноразовым init.
- Не переходить к следующему этапу автоматически. После проверки остановиться для обсуждения результата.
- Выбирать простой код, небольшие функции и минимум файлов. Переиспользовать существующие retrieval и RAG; A2A реализовать официальным SDK, без своей реализации JSON-RPC и универсальной архитектуры. Сохранить CPU-PyTorch и фиксировать версии прямых зависимостей.
- Общаться по-русски. Перед каждым логическим блоком объяснять действие и его цель; после изменений объяснять назначение файлов, ключевые параметры и команды запуска.
- Проверять результат каждого законченного этапа и объяснять фактические результаты команд, ошибки и ограничения.
- Учитывать существующие файлы и не перезаписывать чужие изменения. Не удалять существующие контейнеры и volumes для устранения ошибок без необходимости.
- Окружение: Windows, PowerShell, 16 ГБ RAM, Docker Desktop. GPU не подтверждена: использовать CPU.
- Запускать Python явным путём `.venv\Scripts\python.exe`; активация окружения и изменение ExecutionPolicy не требуются.
- Не использовать внешние API генерации и обучение моделей.
- Сохранить результаты этапов 1–7, модели, volumes, 666 points и локальный CLI из .venv. Не пересчитывать embeddings документов и не скачивать SQuAD заново. Модель, prompt, алгоритм и параметры не менять.
- Не использовать test для настройки и не печатать все его вопросы и ответы.
- Не использовать test.jsonl, не повторять полную dev-оценку. Не передавать эталоны, answer_starts и expected_doc_id модели или пользователю API.
- Сохранять точные подстроки документов и проверять реальные границы, длину без truncation и порядок строк матрицы.
- Не устанавливать CUDA-пакеты. Кеш модели размещать в игнорируемой .cache/ проекта.
- Qdrant запускать в Docker только с локальным HTTP-портом и постоянным volume. Не удалять коллекции или volumes автоматически.
- Для points использовать детерминированные UUID5 из chunk_id; payload совместим с LangChain: page_content и metadata.
- Модель вопросов загружать из существующего кеша по ревизии embeddings_manifest.json, только на CPU, одну копию на процесс. Проверять предел входа без truncation.
- RAG: проверка вопроса, существующий top-3 retrieval, контекст S1/S2/S3 с названиями, ChatPromptTemplate и ChatOllama. Источники формировать из retrieval, не из ответа модели.
- Генерация: qwen3:4b-instruct-2507-q4_K_M, temperature=0, num_ctx=2048, num_predict=64, keep_alive=5m, HTTP timeout=300 с. Не включать tools, reasoning или историю; каждый вызов независим.
- Фиксировать prompt до проверки. Oracle/retrieved используют одну инструкцию и один LLM; между режимами меняется только контекст.
- На этапе 8 проверить init, контейнерные HTTP/SDK-запросы, Spectre/box cooker, повторный запуск, перезапуск и пересоздание без удаления volumes, сохранность данных/весов. Сохранить реальные результаты в results/docker_check.json; старые отчёты не перезаписывать.
- EM и token F1 считать по официальному определению SQuAD; исходные ответы сохранять без исправлений. Отдельная проверка Orivexa не входит в метрики dev.
- Проверять бюджет Qwen-контекста и сохранять prompt_eval_count. Снимки docker stats не называть пиком; при сбоях/таймаутах остановить оценку, сохранив результаты. Не менять Windows/WSL или размер модели автоматически.
- В контейнерах API и агент слушают 0.0.0.0:8000/9999, один worker, без reload. На Windows API публикуется только 127.0.0.1:8000; старые локальные команды остаются дополнительным вариантом. Не запускать локальный и контейнерный Python-агент одновременно.
- API-образ: только FastAPI/A2A, без PyTorch/sentence-transformers. API не загружает ML-модели; прямой fallback запрещён. Агент использует одну MiniLM и существующий RAG на CPU, без генерации при старте; блокировка и threadpool остаются в агенте.
- Адреса через env с прежними локальными defaults: в Compose Ollama=http://ollama:11434, Qdrant=http://qdrant:6333, агент=http://agent:9999. Agent Card публикует рабочий внутренний адрес; SDK проверять из Compose-сети, без ручной подмены адреса.
- Использовать Python 3.11 slim и совместимые Linux wheels; не копировать .venv или веса в образы, не устанавливать CUDA. Сохранить версии зависимостей, а несовместимость объяснить и проверить.
- init ограниченно ждёт доступность Ollama/Qdrant, проверяет Qwen и скачивает только при отсутствии, готовит точные ревизии MiniLM/токенизатора, проверяет артефакты и импортирует готовые векторы существующим index_qdrant.py. Повторный запуск без дубликатов/удаления коллекций. Агент стартует после успешного init, без короткого общего timeout скачивания.
- Сохранить имя проекта mini-helpdesk-rag и существующие ollama_data/qdrant_data. data/processed монтировать read-only; для кеша моделей использовать named volume. Закрепить версии/digests образов; не обновлять существующую Ollama автоматически.
- Healthchecks лёгкие, без генерации; можно использовать стандартную библиотеку Python, не предполагать наличие curl. Без циклов зависимостей, произвольных лимитов памяти и изменений Windows/WSL. docker stats — снимок, не пик.
- Использовать только API выбранной стабильной версии официального a2a-sdk; зафиксировать SDK и протокол. Agent Card: Mini Helpdesk Knowledge Agent, skills search_knowledge и answer_question; JSON-RPC, без streaming/push. Структурированный data-part внутри Message: operation, question, top_k только для search. Никаких самодельных числовых JSON-RPC error codes, истории и автономных циклов.
- /health лёгкий; /ready с короткими таймаутами, без генерации и загрузки Qwen. Закрывать собственные клиенты при завершении; Docker автоматически не останавливать. Адрес агента задаётся конфигурацией.
- Проверять запросы Pydantic: trim, непустая строка до 2000 символов, неизвестные поля запрещены, top_k поиска 1–5, для /ask фиксирован 3. Проверка токенового предела сохраняется.
- HTTP-коды: 422 неверный ввод, 503 недоступные зависимости, 504 таймаут генерации/ожидания A2A, 429 занятая генерация, 500 неожиданная ошибка, 502 несоответствие формата ответа агента/ошибка протокола. Причины логировать; traceback не возвращать клиенту. Реальные проверки отличать от имитаций.
- Не включать внешнюю телеметрию. Не добавлять frontend, reranking, новые модели или архитектуру сверх этапа. Ничего не публиковать. Не удалять volumes и не использовать docker compose down -v. После этапа остановиться для обсуждения.
